# Dataverse Admin Agent: Transparency Note

## Overview

The Dataverse Admin Agent is a Microsoft Copilot Studio sample for conversational
security administration in Microsoft Dataverse and Dynamics 365. It helps
authorized administrators retrieve security information and perform two
controlled administrative changes. It does not replace existing administration
tools, access governance, approvals, or periodic access reviews.

Customers must test, validate, and review the sample and any changes before
production use. See the [installation guide](./installation-guide.md) and
[configuration guide](./configuration-guide.md).

## Intended use

The intended audience is authorized Dataverse, Dynamics 365, and Power Platform
administrators, security and governance teams, support and operations teams,
and environment owners with appropriate permissions.

| Supported purpose | Scope |
|---|---|
| Security lookups | Retrieve a single user's security information; look up existing roles, teams, business units, and membership counts |
| Housekeeping | Report disabled users and recorded access when suitable audit data is available |
| Licensing visibility | Retrieve read-only identity and license context through Microsoft Entra ID and Microsoft Graph |
| Controlled writes | Assign one existing security role to one existing user, or add one existing user to one existing team |

The agent is not intended to certify compliance or access reviews, evaluate or
rank individuals, make employment decisions, answer general business questions,
or serve non-administrative business users. It does not support bulk changes,
removals, structural security-model changes, or assigning, removing, or modifying
Microsoft 365 licenses.

## Access and publishing

Microsoft Entra ID sign-in is required in every channel. The agent is not a
public-facing service. All reads and writes run in the signed-in user's own
Dataverse security context; the agent does not bypass Dataverse or Microsoft
Entra authorization.

Customers control publishing and sharing. They should limit access to an
administrator security group or administrator-only channel, not general
business users. Channels may include Microsoft Teams, Microsoft 365 Copilot,
or an authenticated web experience, subject to customer configuration.

## System behavior and the role of AI

The language model interprets intent, extracts parameters, and composes readable
responses. Administrative facts come from configured actions and connected
data sources rather than model memory. The configuration uses versioned
instructions and skills.

Straightforward single-query reads use the Dataverse connection directly.
Audit-dependent, multi-step, disambiguation-heavy, and write requests use the
core skill. Licensing requests use the licensing skill.

The agent is configured to refuse out-of-scope and sensitive requests,
including unrelated general-knowledge questions, judgments about individual
performance, requests for credentials or connection details, compliance
certification, and personal data beyond connected administrative records.
Web browsing, general-model-knowledge answers, file analysis, and semantic
search over uploaded content are disabled, and content moderation is set to
the highest available level.

These configuration controls do not replace human validation. Plausible but
unverified statements about access, activity, or entitlement remain a risk.

## Evaluated model and content provenance

- The agent was evaluated with **Claude Opus 5.5 (Anthropic)** in Microsoft
  Copilot Studio. The evaluated configuration uses model series
  `claude-opus-5-5`.
- Customers may select another model available in Copilot Studio by using the
  unmanaged development and ALM path described below.
- The template does not implement its own watermarking. Text watermarking
  depends on the selected model. We recommend choosing a model with a live
  text watermark.
- Output is text only: no images, audio, video, or files.
- Every response ends with the visible label:
  "AI disclosure: This content was generated by an AI agent."

The visible disclosure applies in every channel and is distinct from
model-dependent text watermarking. Retain the disclosure when forwarding,
copying, or archiving a response. AI-generated answers should not be treated as
human-authored statements or direct system records.

## Human oversight and controlled writes

The administrator remains accountable for interpreting output and authorizing
changes. Only the following writes are supported:

| Operation | Required targets |
|---|---|
| Assign a security role | One existing security role and one existing user |
| Add a team member | One existing user and one existing team |

Each operation requires validation of the targets, a proposed-action preview,
and then the exact word `CONFIRM`. Resolve ambiguous identities and duplicate
names before proceeding. Responses such as "yes", "ok", or "proceed" do not
confirm the action; any other response cancels the pending operation.

Confirmation is operator-bound, single-use, tied to the previewed change, and
expires after five minutes. These controls are enforced in Power Automate,
not by the model. One confirmation authorizes only one change. The agent does
not perform unattended or bulk administrative execution.

Read each preview carefully and follow organizational approval and
change-management processes. Confirmation is not a substitute for those
processes. See the [user guide](./user-guide.md).

## Data handling and privacy

| Connected source or service | Data or function |
|---|---|
| Microsoft Dataverse | Users, business units, teams, security roles, field security profiles, and memberships |
| Dataverse audit or user-access data | Recorded activity when enabled, retained, and accessible |
| Microsoft Entra ID and Microsoft Graph | Identity and read-only license context |
| Microsoft Copilot Studio | Conversation orchestration, topics, actions, authentication, and channel configuration |

The agent processes data the invoking administrator is permitted to see.
Results reflect that administrator's permissions, so two administrators may
receive different answers to the same question. Customer-configured security
and role-based access controls govern access to connected data.

Customers must evaluate their deployment's privacy, retention, regulatory, and
operational requirements. Do not enter credentials, secrets, or unnecessary
personal information into a conversation.

## Limitations and considerations

| Limitation | Implication for operators |
|---|---|
| Connected data may be incomplete, stale, or inaccessible | Validate important output against available records |
| Activity and change history depend on enabled and retained Dataverse auditing | Missing evidence does not establish inactivity |
| Latest recorded access comes only from Dataverse audit records | Missing records are reported as Unknown; record modification dates are not a substitute |
| Intended entitlements may not be stored in connected data | Do not treat inferred entitlements as facts |
| Licensing answers depend on the user's Entra permissions | Missing permission can make licensing information unavailable |
| Role assignment depends on cross-business-unit configuration | Select explicitly when multiple candidate roles exist |
| Local-time reporting requires the administrator's time zone | The agent asks when the time zone cannot be determined |
| Query breadth, environment size, and platform limits affect performance | Validate behavior in the target environment |

Use unambiguous identifiers and respond to clarification prompts rather than
assuming a target has been selected correctly. Treat Unknown audit evidence as
a genuine data gap. Use the agent as decision support, not final authority.

## Evaluation

Evaluation covers groundedness, scope adherence, refusal of out-of-scope and
sensitive requests, disambiguation, and the confirmation contract for both
write operations.

The evaluation approach uses at least 100 English prompts with Microsoft
evaluation tooling and a target success rate of 85-90% or higher. These are
evaluation criteria, not a statement of an achieved score. Evaluation is
re-run when system instructions or skill files change. Customers must validate
their own deployment and any changes.

## Customization and customer responsibility

The managed package is not customizable. Its model and instructions are fixed
to the reviewed configuration. Customers who need a different model or other
changes should import the unmanaged package into a development environment and
manage it through their own application lifecycle management (ALM).

Any change to the model, instructions, tools, flows, channels, or connections
is the customer's responsibility and is outside the configuration Microsoft
reviewed. Customers are responsible for testing, validating, deploying,
operating, and governing the agent in their environments.
